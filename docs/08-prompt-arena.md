# پرامپت چت جدید Arena

هر وقت خواستی در یک چت جدید از Arena همین پروژه را ادامه بدهی،
این بلوک را کامل کپی کن و همان اول بفرست:

```text
من مالک ریپوی https://github.com/Mahditalebian/mushaf-mohasha هستم
(پروژه «مصحف محشی» — دانشنامه معنایی وقف و وصل و ابتدا در قرآن کریم، پایتون خالص).
ریپو را کلون کن و روی همین پروژه کار کن.

قواعد برنچ و دپلوی (خیلی مهم — به آن‌ها پایبند باش):
1. کارها فقط روی برنچ arena/* که این سشن خودش به آن قفل است انجام می‌شود
   و همان‌جا push می‌شود.
2. هیچ‌وقت مستقیم به Staging یا main پوش/کامیت نده.
3. بعد از هر تغییر واقعی: از برنچ آرنا به Staging Pull Request باز کن
   و منتظر تایید من بمان.
4. بعد از مرج شدن در Staging، PR از Staging به main برای مرحله پروداکشن.
5. برنچ‌ها را حذف/تغییرنام/جابجا نکن.

وضعیت فعلی: main و Staging روی کامیت 13843cd هستند؛ برنچ آرنا جلوتر است
و کارهای انجام‌نشده را باید از PR بازش ببینی. اول `gh pr list` و
`git fetch origin` بزن تا وضعیت دقیق را بدانی.
اگر PR با خطای "No commits between" رد شد، یعنی هنوز تغییری نساخته‌ای —
اول کار انجام بده بعد PR بزن.

اجرای لوکال: python3 -m engine serve (پورت 8765) و راهنمای کامل در LOCAL.md
بهترین مواضع (ترکیب محشی + علائم چاپی): python3 -m engine best «بقره ۹۱»
و مستندش: docs/09-tarkib.md

[اینجا بنویس دقیقاً چه چیزی بسازم یا تغییر دهم]
```

## چرا این جمله‌ها داخل پرامپت است؟

- **نام برنچ استیج** صریح آمده (`Staging`) چون اگر مدل اشتباه املایی کند
  (مثلاً `Staiging` قدیمی یا `Staging ` با فاصله) PR درست ساخته نمی‌شود.
  اگر برنچ نبود، بگو اول `gh pr list` بزند تا نام واقعی را ببیند.
- **وضعیت کامیت‌ها** گفته می‌شود تا ایجنت جدید بداند از کجا شروع کند
  و کارهای قبلی را دوباره انجام ندهد.
- **خطای "No commits between"** از قبل توضیح داده شده چون گیتهاب وقتی
  بین دو برنچ کامیت جدیدی نباشد اجازه PR نمی‌دهد — یعنی اول باید کار واقعی انجام شود.

## جریان استاندارد

```
برنچ آرنا (میز کار سشن)
        │ push + commit
        ▼
     Staging    ←── PR اول: تست و تایید
        │
        ▼
       main     ←── PR دوم: پروداکشن
```

مرج نهایی همیشه با تایید مالک انجام می‌شود.
